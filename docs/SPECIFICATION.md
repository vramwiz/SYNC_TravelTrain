# AviUtl2プラグイン「旅行列車」開発仕様

## 1. プロジェクト概要

- プロジェクト名：SYNC_TravelTrain
- グループ名：SYNC
- 日本語プラグイン名：旅行列車
- シリーズ名：Travelシリーズ
- 開発言語：Delphi

将来的にバス、船舶、飛行機などの旅行演出プラグインを開発する可能性があるため、Travelシリーズとして命名する。

列車を利用した旅行シーンを簡単に制作するための演出プラグインとする。鉄道シミュレーターではなく、立ち絵を使用した動画制作を主な用途とする。

## 2. 基本設計方針

一般的な立ち絵は正面を向いているため、正面向きの立ち絵で自然な演出が成立する構図を採用する。

一連の旅行演出を以下の5種類のシーンに分割する。

1. 到着
2. 乗車
3. 走行
4. 降車
5. 発車

各シーンは完全に独立した演出とする。

シーン間でカメラ位置、構図、座標などを連続させる必要はない。映像としてシーンを切り替えることを前提とし、それぞれのシーンに適した構図で描画する。

立ち絵の描画、移動、拡大率の調整、レイヤー間の移動はユーザーが担当する。

プラグイン側では立ち絵を直接管理しない。

## 3. プリセット

パラメーターの上部にプリセット設定を設ける。

### 列車プリセット

車両形状、車体色などを一括設定する。

以下のような列車を想定する。

- 通勤電車（ステンレス車体）
- 通勤電車（塗装車体）
- 特急電車（箱型）
- 特急電車（流線型）

プリセット適用後、車体色や帯色などをユーザーが個別に変更できるようにする。

### シーンプリセット

- 到着
- 乗車
- 走行
- 降車
- 発車

シーンを選択すると、そのシーンに適した初期パラメーターを設定する。

## 4. レイヤー制御

各シーンで必要となる描画対象について、個別に描画ON／OFFを指定できるチェックボックスを設ける。

初期状態ではすべてONとし、1オブジェクトのみで演出が完成するものとする。

立ち絵を配置する場合は、ユーザーがオブジェクトを複製し、描画対象のチェックを変更することで必要なレイヤーに分離する。

描画対象のON／OFFによって時間計算や描画位置が変化しないようにする。

同じ設定、同じ再生位置であれば、分離したレイヤー同士が正確に一致するようにする。

| シーン | プラグインの描画レイヤー数 |
|---|---|
| 到着 | 2 |
| 乗車 | 3 |
| 走行 | 2 |
| 降車 | 2 |
| 発車 | 1 |

## 5. 時間パラメーター

時間に関係するパラメーターは専用グループにまとめる。

- 時間の単位は秒とする。
- 0.01秒程度の単位で調整可能とする。
- 時間を0に設定した場合、その演出を省略する。
- 各工程の時間を累積し、現在の再生位置から演出状態を計算する。
- オブジェクトの途中から再生した場合やシークした場合でも、正しい状態を描画する。

扉の開閉は必ずペアとして扱う。

開扉時間と閉扉時間のどちらか一方が0の場合は、両方の演出を省略する。

開放時間は独立して管理する。開閉時間が0で開放時間だけが設定されている場合は、扉を閉じたまま待機する。

ユーザーの設定が現実的であるかどうかは問わないが、描画や演出が破綻しないようにする。

## 6. シーン1：到着

### 演出内容

ホームで待っている人物の手前を列車が通過し、減速して停止する演出とする。

立ち絵が正面を向いていても自然に見えるよう、列車は人物より手前を走行する。

列車全体の動きが分かる引きの構図を基本とする。

扉の開閉は行わない。

### レイヤー構成

奥から手前の順序は以下とする。

1. ホーム背景（プラグイン）
2. 立ち絵（ユーザー）
3. 列車本体（プラグイン）

プラグインは2レイヤー構成とする。

### 時間パラメーター

- 到着前待機時間
- 到着時間
- 停止後待機時間

### 演出範囲

列車なし → 列車進入 → 減速 → 停止

停止時は扉が閉じている状態とする。

## 7. シーン2：乗車

### 演出内容

到着シーンから構図を切り替える。

列車内側からホームを見る構図とし、扉を中心としたアップの構図とする。

列車はすでに停止している状態で開始する。

列車本体は動かさず、扉のみを開閉する。

正面を向いている立ち絵がホームから手前に向かって移動することで、乗車演出が成立する構図とする。

### レイヤー構成

奥から手前の順序は以下とする。

1. ホーム背景（プラグイン）
2. 乗車前の立ち絵（ユーザー）
3. 扉（プラグイン）
4. 乗車後の立ち絵（ユーザー）
5. 車内（プラグイン）

プラグインは3レイヤー構成とする。

扉が開いている間に、ユーザーが立ち絵の座標や拡大率を調整し、扉レイヤーを跨いで移動させる。

### 時間パラメーター

- 開扉前待機時間
- 開扉時間
- 開放時間
- 閉扉時間
- 閉扉後待機時間

### 演出範囲

停車・扉閉 → 開扉 → 乗車待機 → 閉扉 → 停車・扉閉

発車は担当しない。

## 8. シーン3：走行

### 演出内容

乗車シーンから構図を切り替える。

列車の外側から窓越しに車内を見る構図を基本とする。

正面を向いた立ち絵を車内の乗客として配置できるようにする。

列車の描画位置は固定し、背景を移動させることで走行を表現する。

これにより、ユーザーが列車の移動に合わせて立ち絵の座標を変更する必要がないようにする。

走行に関係する複雑な描画処理はこのシーンに集約する。

### レイヤー構成

奥から手前の順序は以下とする。

1. 走行風景・車内・座席（プラグイン）
2. 立ち絵（ユーザー）
3. 車体・窓枠・窓ガラス・前景物（プラグイン）

プラグインは2レイヤー構成とする。

扉の開閉は行わない。

### 時間パラメーター

- 発車前待機時間
- 加速時間
- 走行時間
- 減速時間
- 停止後待機時間

### 走行背景

エレベーター演出プラグイン（SYNC_Elevator）で使用した背景描画技術を参考にする。

走行する高さをパラメーターとして設定できるようにする。

- -1：地下・トンネル
- 0：地上
- 2以上：高架

-1から0の範囲は地下およびトンネルへの進入・脱出表現に使用する。

地上から高架への高さ変化についても自然に表現できるようにする。

地下とトンネルは共通の描画処理で対応する。

### 走行関連の検証項目

以下については実際に描画して検証し、品質や処理負荷を確認したうえで採否を判断する。

- 遠近感のある背景スクロール
- 走行速度と速度変化
- ズームによるアップ・引きの構図
- 背景の種類
- 電柱などの通過物
- 対向列車とのすれ違い
- 車体の振動
- 高速走行時のモーションブラー

ズームによって列車全体を見せる構図から、窓越しに立ち絵の表情を見せる構図まで対応できることが理想である。

ただし、立ち絵と列車の位置関係が破綻する場合や、処理負荷が大きくなる場合は無理に実装しなくてもよい。

乱数を使用する場合はシード値を設け、同じ設定で再生するたびに演出が変化しないようにする。

### 演出範囲

停車 → 発車 → 加速 → 走行 → 減速 → 停止

到着した状態までを担当し、扉は開かない。

## 9. シーン4：降車

### 演出内容

走行シーンで列車が停止した後、構図を切り替える。

ホーム側から列車の扉を正面に見るアップの構図とする。

乗車シーンとは視点が反対になることに注意する。

正面を向いた立ち絵が車内から手前に向かって移動することで、降車演出が成立するようにする。

列車は固定し、扉のみを開閉する。

### レイヤー構成

奥から手前の順序は以下とする。

1. ホーム・列車本体・車内（プラグイン）
2. 降車前の立ち絵（ユーザー）
3. 扉（プラグイン）
4. 降車後の立ち絵（ユーザー）

プラグインは2レイヤー構成とする。

レイヤー数を抑えるため、列車の屋根や扉の枠などを独立した前景レイヤーにはしない。

厳密な3D構造ではなく、立ち絵を中心として違和感のない疑似立体表現とする。

ユーザーが立ち絵の位置と拡大率を調整し、扉の枠などに不自然に干渉しないようにする。

### 時間パラメーター

- 開扉前待機時間
- 開扉時間
- 開放時間
- 閉扉時間
- 閉扉後待機時間

乗車シーンと共通の扉開閉処理を利用する。

### 演出範囲

停車・扉閉 → 開扉 → 降車待機 → 閉扉 → 停車・扉閉

発車は担当しない。

## 10. シーン5：発車

### 演出内容

降車シーンから構図を切り替え、引きの構図とする。

ホームに降りた人物の奥を列車が走行し、画面外へ消える演出とする。

ホームと列車をまとめて背景として描画する。

### レイヤー構成

奥から手前の順序は以下とする。

1. ホーム・列車本体（プラグイン）
2. 立ち絵（ユーザー）

プラグインは1レイヤー構成とする。

扉は常に閉じた状態とし、独立した扉描画は行わない。

### 時間パラメーター

- 発車前待機時間
- 発車時間
- 発車後待機時間

### 演出範囲

停車 → 発車 → 加速 → 列車なし

## 11. 列車の共通描画仕様

列車の種類は通勤電車と特急電車を基本とする。

先頭車両と最後尾車両が流線型になっている形状についても対応してよい。

機関車牽引型は初期実装の必須対象としない。

正確な編成数や車両数を管理する必要はない。

中間車両の繰り返し描画や、描画範囲外の車両の省略などを利用して、車両数を自然に見せる工夫を行う。

車両の形状や色は各シーンで共通化し、同じプリセットを使用した場合は同じ列車に見えるようにする。

以下の設備は描画不要とする。

- 車輪
- 台車
- パンタグラフ
- 架線

構図やホームなどによって車体下部を隠し、省略した設備が目立たないようにする。

電柱などは背景物として描画してもよい。

## 12. 背景の共通仕様

ホームや走行風景などの背景は、原則として描画範囲全体を埋めるようにする。

列車や人物を配置した際に、不必要な透明部分や背景の欠落が発生しないようにする。

ただし、レイヤー分離のために描画対象をOFFにした場合は、その対象を透明として扱う。

実在する駅や列車を忠実に再現する必要はない。

立ち絵動画の背景として自然に見えることを優先する。

## 13. その他の共通仕様

- X座標
- Y座標
- 拡大率
- 透明度
- 描画範囲の幅・高さ
- 車体色
- 帯色などの配色設定

必要に応じて基本的な描画調整パラメーターを用意する。

パラメーターは用途ごとにグループ化し、設定項目が過度に多くならないようにする。

音声および効果音は実装しない。

時計および時刻管理機能は実装しない。

自動車、バス、船舶、飛行機などには対応しない。

## 14. 描画負荷への配慮

各シーンでは、そのシーンに必要な描画処理のみを実行する。

到着や発車シーンで走行風景を生成する必要はなく、乗車や降車シーンで列車を移動させる必要もない。

静止している背景や車両などについては、可能な範囲で描画結果をキャッシュする。

乗車・降車シーンでは主に扉のみを動的に描画する。

走行シーンについては特に処理負荷に注意し、モーションブラーなどの高負荷処理は品質と速度を検証してから採用する。

## 15. 開発・検証方針

既存のSYNCシリーズ、特にエレベーター演出プラグインの実装を参考にする。

5種類のシーンを独立して実装・検証する。

すべてのシーンを連続した1つの演出として処理する必要はない。

まずは基本的な構図とレイヤー分離が成立することを優先し、その後に描画品質を向上させる。

特に以下を重点的に確認する。

- 正面向きの立ち絵で各シーンが自然に成立すること
- レイヤー分離前後で描画位置や演出時間が一致すること
- 乗車と降車で視点が正しく反転していること
- 扉の開閉時に描画が破綻しないこと
- 時間を0に設定した場合に正しく演出が省略されること
- 走行中に立ち絵の座標を変更する必要がないこと
- 各シーンで列車のデザインが統一されていること
- 処理負荷が実用的な範囲に収まること

鉄道設備の正確な再現よりも、旅行動画としての演出品質、ユーザーの操作性、描画速度を優先すること。

仕様を満たすために極端に複雑な処理が必要となる場合は、描画が破綻しない範囲で簡略化してよい。
